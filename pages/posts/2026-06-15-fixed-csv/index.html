Comptime is fun time

For a recent project we had to write a columnar CSV parser with a fixed schema and decided to use Zig for this.

The CSV files we were supposed to read were all with a set of compile-time known schemas, about 13 different ones. After parsing we needed to efficiently access the records in a columnar way. We could not use a columnar format like Arrow, we had to read CSV files.

Schema

We decided to use MultiArrayList to represent slices of records in a columnar way. In our case some of the data we dealt with encoded linear constraints we passed to solvers like HiGHs or Gurobi.


// Each row is in COO (coordinate list).
const SparseMatrixRow = struct {
    row: u64,
    col: u64,
    value: f64,
};

const SparseMatrix = MultiArrayList(SparseMatrixRow);

The record type is our schema. We want to compile a specialized reader for this particular schema, parsing CSV records and returning or filling a MultiArrayList.

We want to support a subset of primitive types in Zig, notably also optionals.

Tokenizer

We implement a simple tokenizer (heavily inspired by the Zig languages compiler tokenizer).


const Tokenizer = struct {
    buffer: [:0]const u8,
    index: usize,

    // Each token has a tag and a location in the source.
    const Token = struct {
        tag: Tag,
        loc: Loc,

        // Index points into the source where the value of this token
        // starts.
        const Loc = struct {
            start: usize,
            end: usize,
        };

        // Kind of token.
        const Tag = enum {
            field,
            delimiter,
            clrf,
            invalid,
            eof,
        };
    };

The tokznier contains a zero-terminated slice, the CSV file we are reading, and it produces tokens. Each token points to some data in the buffer and has a tag. When looking at rfc4180 we know that a valid CSV file does not have so many different tokens.

The tokenizer reads each byte from the source and we have a simple state machine to decide what kind of token we are dealing with:

    // State of the tokenizer.
    const State = enum {
        start,
        eof,
        quote,
        field,
        delimiter,
        clrf,
        invalid,
    };

    // Produce the next token.
    pub fn next(self: *Tokenizer) Token {
        var result: Token = .{
            .tag = .field,
            .loc = .{ .start = self.index, .end = undefined },
        };

        state: switch (State.start) {
            .start => {
                switch (self.buffer[self.index]) {
                    '"' => {
                        // Quoted fields should not contain the quote
                        // itself.
                        result.loc.start = self.index + 1;
                        continue :state .quote;
                    },
                    // ... other cases ...
            },
            // ... other states ...
        }
        return result;
};

We read on byte after the other and use Zigs new continue :state to do a state transition. The statemachine encodes the CSV syntax. The only way for us to go into the .invalid state is when a plain .field contains a quote. That is not allowed.
